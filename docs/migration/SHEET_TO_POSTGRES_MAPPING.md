# Sheet-to-PostgreSQL Mapping

Version: v1.0.0 source model → v2 target schema

This mapping was completed before the Stage 2 SQL migrations were written. It is based on the v1.0.0 tag, the deployed Apps Script v1.0.0 source, the production API's read-only column metadata for Teams, Competitors and Events, and every Apps Script service that reads or writes the remaining sheets.

PostgreSQL names use `snake_case`. Existing stable IDs remain `text`; the migration does not force existing UUID-shaped strings into PostgreSQL's `uuid` type. `created_at` and `updated_at` are new database-maintained metadata and therefore have no Sheet source column.

## Deliberately derived, not migrated as tables

| Current concept | PostgreSQL representation | Reason |
|---|---|---|
| Live leaderboard | Query/service over `events`, current `event_runs`, `results`, `point_profiles` and active `teams` | v1.0.0 calculates totals dynamically. A totals or leaderboard table would create a second source of truth. |
| Event History | Query/service over all run-scoped engine rows and `results` | v1.0.0 reconstructs history; it has no snapshot/history sheet. |
| Confirmed state | Existence/count of `results` for an Event Run | The current application has no confirmation flag column or table. |
| Event current run | `event_runs.is_current`, a partial unique index and a deferred exact-one constraint trigger | The Events sheet has no `CurrentRunID`; adding a competing pointer would permit inconsistent ownership. |

## Cross-cutting transformation rules

- Preserve every existing `ID` and every foreign-key value exactly as text.
- Convert blank optional values to SQL `null`; never convert zero or `false` to null.
- Convert `TRUE`/`FALSE` and native Sheet booleans to PostgreSQL booleans.
- Validate required headers before reading rows. Extra or missing headers are reportable migration errors unless explicitly covered above.
- Derive `sequence_number` as a one-based counter within each `EventRunID`, following original Sheet row order.
- Do not import blank-`EventRunID` engine rows until the existing deterministic Run 1 ownership rule has been applied.
- Import a single event and all its runs in one transaction so every event ends with exactly one current run.
- Preserve `Events.Status` as imported compatibility state, then validate it equals the current run's status.

## API-stage ordering and constraint additions

Migration `202609220001_api_transactions.sql` adds `source_order` identity columns to Teams, Competitors, PointProfiles, Events, EventRuns, EventCompetitors and DoubleTeamMatches. Capture original Sheet row order in these columns during import and advance identity sequences afterwards. Engine/result tables continue to use per-run `sequence_number`. Race final-position uniqueness and Distance position uniqueness now validate at transaction completion so existing placings can be swapped atomically.
